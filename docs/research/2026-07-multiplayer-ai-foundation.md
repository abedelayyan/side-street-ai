# Multiplayer AI for Coding Agents: Technical and Strategic Foundation

## TL;DR

- Build a **shared, durable coding-agent session layer** on Cloudflare Durable Objects (one Durable Object per session, WebSocket Hibernation for fan-out, embedded SQLite as the append-only event log), stream tokens to N viewers via offset-based resumable streams, and run the actual agent inside a per-session microVM sandbox (E2B or Vercel Sandbox). Do not build your own agent; wrap Claude Code and Codex through the Agent Client Protocol (ACP) so existing harnesses provide the intelligence and you own the collaboration surface.
- The core unsolved problem is **concurrent human steering**, not infrastructure. Every shipping coding agent (Claude Code, Codex, Cursor) already resolved single-user steering the same way: queue human input and inject it at the next tool-call boundary, with an explicit hard-interrupt escape hatch. No shipping product handles *multiple* humans steering one agent. That gap, plus per-viewer secret redaction and tamper-evident attribution, is where a solo founder can build something defensible before the incumbents get to it.
- The wedge is **engineering incident response and pair/mob debugging**, not greenfield coding. The buyers are platform and on-call engineering teams who already crowd around one broken production problem. Defensibility is thin against Anthropic, GitHub, and Cursor, all of whom are actively prototyping this (GitHub Next’s “Ace,” Zed’s multiplayer buffers, Anthropic’s Claude Tag). Win on being agent-agnostic, on the steering-and-attribution model, and on speed, not on the base agent.

## Key Findings

### The RFS and what it actually asks for

Aaron Epstein’s “Multiplayer AI” entry in YC’s Fall 2026 RFS is explicit: “Anyone on a team should be able to drop into the same live agent session to watch it work, redirect it, and hand it off, the way they’d work with any other human team member.” The framing is Google Docs and Figma for agents, and the stated trigger is that “agents are starting to run tasks that take hours, days, even weeks.” The application deadline was July 27, 2026. The RFS names engineering explicitly (“Shared agents for engineers coding together in real time”) as the first of several verticals.

### The competitive field is crowded but nobody has shipped true multiplayer steering

As of mid-2026, the market has split into three tiers, and there is a real gap at the top.

- **Parallel-agent orchestration (single human, many agents).** Conductor (Melty Labs, YC S24) runs multiple Claude Code, Codex, and Cursor agents in parallel, each in an isolated git worktree, with a Mac-native diff-review UI. Per Conductor’s own blog, it raised a $22M Series A led by Ilya Sukhar at Matrix (who also led the seed and joined the board), with Nabeel Hyatt at Spark, Y Combinator, and the founders of Notion and Linear participating; it cites 10x user growth since January 2026 and Google, Meta, Datadog, Block, and Rippling among users. It moved execution to the cloud on Vercel Sandbox via “Cloud Workspaces.”  Claude Code’s own experimental **Agent Teams** (shipped with Claude Opus 4.6 on February 5, 2026; enable with `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`) coordinates 2 to 16 Claude instances through a shared task list and inter-agent messaging. Vibe Kanban, Google Antigravity’s Mission Control, and Claude Squad occupy the same tier. All of these are one human directing many agents, not many humans sharing one agent.
- **Collaborative editors with agents (multi-human, agent as assistant).** Zed ships multiple humans and multiple agents in one buffer with shared channels and threads, the closest thing to true multiplayer today, but the humans collaborate on the *code*, and the agent is a participant rather than a shared steerable object. Microsoft added agents-as-teammates in Teams at Build 2026.
- **Research prototypes aimed squarely at the RFS thesis.** GitHub Next’s **Ace** (first public demo early 2026, entering technical preview) is the most direct precedent: “a realtime, multiplayer coding agent workspace… like Slack, GitHub, and Claude/Copilot had a baby.”  Each session is backed by a sandboxed cloud microVM on its own git branch; teammates join instantly without pulling branches; sessions persist independently of any laptop;  and multiple people can prompt the same agent (“multiplayer prompting”), with the agent reading the whole conversation as input. This is essentially the product the RFS describes, built by GitHub, and it is the clearest signal both that the idea is real and that the incumbents are already on it.

Anthropic’s **Claude Tag** (launched June 23, 2026, beta for Claude Enterprise and Team, built on Claude Opus 4.8) is the most important shipped multiplayer-adjacent product. It puts one shared Claude identity into a Slack channel; any member can tag @Claude, it retains channel context over time, and it can keep working after you stop typing. Per Tech Times (June 23, 2026), Anthropic already routes 65% of its own code through an internal version of Claude Tag; separately, Anthropic’s January 29, 2026 contribution-metrics release reported that internal engineers “merge 67% more PRs per day” and that “70-90% of code across teams is now written with Claude Code assistance.” Claude Tag is asynchronous and Slack-thread-shaped, not a live shared session you watch token-by-token, and Anthropic frames it as “the beginning of an evolution of Claude Code.” There is an open feature request (issue #60082) on the Claude Code repo asking for exactly the live multi-user single-session collaboration the RFS describes; Anthropic has not shipped it. That is the specific gap.

### Durable execution: Cloudflare Durable Objects is the right spine for a solo TS founder

The session needs to survive for hours to weeks, hold state across restarts, accept mid-run intervention, and fan out to many subscribers. Comparing the candidates:

- **Cloudflare Durable Objects** give you a single-threaded actor with a globally unique name, an embedded SQLite database that is strongly consistent, WebSocket Hibernation so an idle session with connected viewers costs nothing in duration billing, and Alarms for scheduling. The Cloudflare Agents SDK (the `Agent` class, built on PartyServer) wraps this with `onStart`, `onConnect`, `onMessage`, and `this.broadcast`. Concrete 2026 limits: WebSocket message size raised from 1 MiB to 32 MiB (October 31, 2025);  10 GB storage per object; key+value combined cannot exceed 2 MB; 30 seconds CPU per request, configurable to 5 minutes; 500 DO classes per account on paid.  Pricing: incoming WebSocket messages billed at a 20:1 ratio (20 messages counts as 1 request), 1 million requests/month included then $0.15/million, 400,000 GB-s/month included then $12.50/million GB-s,  and SQLite storage billing began January 7, 2026.  A moderately trafficked realtime app in Cloudflare’s own example (100 objects, 50 WebSocket connections each, one message per minute for 8 hours daily) costs about $138.65/month.  The single-threaded-per-object model is a natural fit for one authoritative agent session with many observers.
- **Temporal** is the mature workflow-as-code durable engine. Per Temporal’s February 17, 2026 press release, it raised a $300M Series D at a $5B valuation led by a16z, with Lightspeed and Sapphire joining and insiders Sequoia, Index, Tiger, GIC, Madrona, and Amplify participating; it cited 380% year-over-year revenue growth and OpenAI, Block, ADP, and Yum! Brands as customers, and a Replay 2026 wave adding Workflow Streams for LLM output and an OpenAI Agents SDK integration. It is the strongest choice for mission-critical polyglot orchestration but carries an operating and learning cost (deterministic workflows, event-history replay) that a solo founder does not need for the session layer.
- **Inngest** and **Trigger.dev** are the TypeScript-native durable-step options with the fastest path to a first durable function; Inngest raised a $21M Series A (Altimeter, September 2025) and ships AgentKit. **Restate** is a lightweight durable runtime whose `ctx.run()` gives exactly-once-per-journal-entry semantics.  **DBOS** puts durable execution next to your Postgres. **LangGraph** persistence (checkpointers writing to Postgres/Redis/SQLite, the `interrupt()` primitive,  `interrupt_before`/`interrupt_after`, time-travel via `get_state_history`) is the best-documented human-in-the-loop model and is worth adopting *inside* the agent process even if the session spine is Durable Objects.

The decision: use **Durable Objects as the session actor and event log**, and if you need cross-service durable orchestration later (for example compensating a failed deploy), add Inngest or Restate as a second layer rather than replacing the DO. Durable execution added single-digit-millisecond overhead per step in one 2026 benchmark,  negligible against LLM latency.

### Real-time sync: this is not collaborative text editing, so do not reach for a CRDT first

The key structural insight, which the RFS framing of “Figma for agents” obscures, is that an agent session is **single-writer for the bulk of the stream** (the agent emits tokens and tool calls) with **bursty multi-writer human input** (steering messages, approvals). That is an append-only event log with fan-out, not a concurrently-edited document.

- **Event-sourcing on the Durable Object’s SQLite** is the right primary model: every agent token, tool call, tool result, and human intervention is an ordered, numbered event. Late joiners replay from a checkpoint rather than from event zero.
- **CRDTs** (Yjs, Loro, Automerge) matter only for the sub-surfaces that are genuinely co-edited: a shared plan document, a scratchpad, cursors and presence. Among these, Yjs is the production default (roughly 920K weekly downloads, the largest binding ecosystem), Loro is the fastest in benchmarks but youngest (roughly 12K weekly downloads), and Automerge is the choice when Git-like version history is a product feature. For presence and cursors specifically, a managed layer (Liveblocks, PartyKit) saves weeks; Liveblocks Pro is $25/month, Team is $500/month. 
- **Streaming to N subscribers with late-joiner replay.** The AI SDK’s `resumable-stream` (Redis-backed) solves the page-reload case only;  the Ably and Upstash writeups are explicit that it does not cover tab switches, multi-device fan-out, or true offset-based catch-up. Vercel’s Workflow DevKit adds `startIndex`-based resumption with an `x-workflow-stream-tail-index` header for relative (negative-index) catch-up,  which is the pattern you want: a reconnecting or late-joining viewer requests “from offset N” and gets only the delta. Since your event log already lives in the Durable Object’s SQLite, you can implement offset-based replay directly against it and avoid a separate Redis dependency, which is the specific limitation Cloudflare users hit with the Vercel package. 
- **Checkpointing and compaction.** Snapshot session state periodically (agent context summary plus a materialized view of the file tree and diff) so a late joiner loads one checkpoint plus the tail of events, not thousands of tokens. This mirrors the Yjs-over-Durable-Objects pattern of periodically vacuuming partial updates to R2.

### Concurrent human steering: the actual hard problem, with concrete prior art

Here is what every shipping coding agent already does for the *single*-user case, which is the foundation you extend to multiplayer:

- **Claude Code.** Per the official docs, typing a correction and pressing Enter “send[s] it without stopping the running tool”; “Claude reads it as soon as the current action completes and adjusts before deciding its next step.” Escape “stop[s] Claude immediately. The running tool call is canceled.” Double-Escape opens a rewind menu (checkpoint restore); Claude snapshots file contents before each edit. The docs explicitly flag the boundary: “Actions that affect remote systems (databases, APIs, deployments) can’t be checkpointed, which is why Claude asks before running commands with external side effects.” There is a well-documented history (issues #36326, #60657, #64624) where type-and-Enter only queued and did not interrupt, and the docs wording was later softened to match; a first-class “inject into the running model turn” channel remains an open request. Claude Code also exposes `/btw` for a side question that “runs independently and doesn’t interrupt the main turn,” and `Ctrl+X Ctrl+K` to stop all running background subagents.
- **OpenAI Codex CLI** distinguishes **steer** (inject into the running turn) from **queue** (run after the turn). Its queued-message UI reads “Messages to be submitted after next tool call (press esc to interrupt and send immediately).” An experimental “steer conversation” mode (codex-cli 0.87.0, January 2026) injects a prompt into the active turn.
- **Cursor** (changelog 1.4) injects steering messages “at the next ideal time, usually after a tool call”; Alt+Enter queues until done, Cmd+Enter interrupts the agent to send immediately, and the default is configurable under Settings, Chat, Queue messages.
- **Agent Client Protocol (ACP, Zed and JetBrains).** JSON-RPC 2.0 over stdio. `session/prompt` begins a turn and returns a `stopReason` (`end_turn`, `max_tokens`, `refusal`, `cancelled`). `session/cancel` is a fire-and-forget notification: on receipt the agent SHOULD “stop all language model requests as soon as possible, abort all tool call invocations in progress, send any pending session/update notifications, and respond to the original session/prompt request with StopReason::Cancelled.” `session/request_permission` is a first-class permission handshake fired before a sensitive tool call, whose outcome is either a user-selected option or `cancelled`. `session/update` streams progress (agent_message_chunk, tool_call with status pending, tool_call_update with status transitions). ACP has **no separate steering method**: mid-turn intervention is cancel-then-reprompt at turn granularity.

The consensus mechanism across all four is the same and it is your starting point: **queue human input, drain it at the next tool-call or step boundary, and expose an explicit hard-interrupt for the impatient case.** The academic literature on mixed-initiative and shared control (largely from robotics and autonomous driving, e.g. Chiou et al.’s negotiation-theory approach to control-authority transfer,  and the CASA line of work extended to multi-agent social groups at CSCW 2025) confirms the general principle: robust shared control requires that humans are “actively involved and adequately informed”  and that control-authority transfer be explicit and consensual rather than a free-for-all of overrides.

For *multiple* humans, no product has solved this, so the plan must specify it. The defensible model, built from the prior art:

- **Roles and steering rights.** Driver (can steer and approve tools), Navigator (can suggest, queued behind driver), Observer (read-only). This maps onto Scholtz’s HRI role taxonomy (supervisor, operator, teammate, bystander)  and onto the view/suggest/write scopes users requested in Claude Code issue #60082.
- **Intervention queue drained between steps**, with author attribution on every queued message, so the agent (and the humans) see who said what. This is the Codex/Cursor default extended with identity.
- **Explicit control handoff** (a “take the wheel” token) rather than optimistic concurrent injection, because concurrent injection into one context window produces incoherent prompts. Reserve optimistic injection for the hard-interrupt path and surface conflicts (“Alice interrupted while Bob’s message was queued”).
- **Compensation, not rollback, for side effects.** Checkpoint-and-rollback (Claude Code’s file snapshots, LangGraph checkpointers) covers reversible local file state only. Partial tool calls that touched remote systems need sagas with compensating actions and idempotency keys derived from (session_id, step_id, attempt). The 2025-2026 research (SagaLLM; the DART and ACRFence arXiv papers on semantic recoverability and rollback attacks) is explicit that naive restore either duplicates a consumed effect or resurrects a lapsed authority, so every side-effecting tool needs a “replay or fork” decision, not a blind rewind.

### Security and multi-tenancy: the exposure surface is the product’s biggest risk

An agent holding repo access and credentials, watched by multiple viewers, is a live data-exfiltration and prompt-injection surface. OWASP’s 2025 LLM Top 10 ranks prompt injection (LLM01) number one for the second edition;  the guidance is blunt that “system prompts are not security controls.”  Anthropic’s own Opus 4.5 system card (November 2025) reported indirect prompt-injection success in agentic coding environments rising with attempts: 4.7% at 1 attempt, 33.6% at 10, 63.0% at 100.  With multiple humans able to steer one privileged agent, you also inherit an insider-risk and machine-insider-risk surface: any steerer can attempt to redirect the agent toward exfiltration.

Required controls:

- **Per-viewer redaction and secret scanning on the outbound event stream.** Scan agent output for secrets before fan-out; redact per viewer role. Observers should never see raw environment variables, tokens, or `.env` contents even if the agent prints them.
- **Least-privilege agent credentials**, scoped per session, short-lived, and never placed in the prompt (OWASP LLM07 system-prompt-leakage guidance).
- **Sandboxing.** Run each session’s agent in an isolated microVM. The 2026 field: E2B on Firecracker microVMs (roughly 150ms cold start,  snapshot-restore to 5-30ms,  pause/resume with filesystem and memory state, roughly 4 seconds per GiB to pause and about 1 second to resume, held indefinitely until killed,  priced around $0.000014/sandbox-second);  Daytona on hardened containers (sub-90ms, as low as 27ms cold starts,  $0.0504/vCPU-hour);  Modal on gVisor (the only one with in-sandbox GPU; per Modal’s May 21, 2026 blog it raised $355M at a $4.65B post-money valuation led by General Catalyst and Redpoint, with Menlo, Bain Capital Ventures, and Accel joining, after growing fivefold since September and surpassing $300M in annualized revenue); Vercel Sandbox (Firecracker, $0.0504/vCPU-hour, Pro $150/month lifts sessions to 24 hours,  tight Next.js fit, and the substrate Conductor chose); Cloudflare Containers/Sandbox (bills in 10ms increments, sleeps to zero, state lives in the adjacent Durable Object).  OpenAI’s Agents SDK v2 (April 15, 2026) baked in seven native sandbox providers,  so treat the sandbox as a swappable layer. For a Durable-Objects spine, Cloudflare Sandbox is the tightest integration; E2B is the isolation-strict default and supports the persistent multi-hour coding session you need.
- **Tamper-evident audit and attribution.** Every steering action, tool approval, and interrupt must be attributed to a named human and hash-chained into the event log so “who steered what” is legible and cannot be quietly rewritten. This is both a security control and a product feature (mob-debugging teams want the postmortem trail).

### Protocols: implement ACP, consume MCP, ignore A2A for now

The 2026 protocol picture settled. **MCP** (donated to the Linux Foundation’s Agentic AI Foundation, formed December 2025 with OpenAI, Anthropic, and Block as founding members)  owns agent-to-tool; its 2025-06-18 revision added elicitation (servers requesting structured input mid-conversation) and structured output, and the 2025-11-25 revision added experimental “tasks” for long-running work and OpenID Connect Discovery.  **A2A** (Google-donated, Linux Foundation, v1.0 April 2026, 150+ organizations)  owns agent-to-agent delegation; ACP the communication protocol folded into A2A in August 2025.  The **Agent Client Protocol (ACP, Zed and JetBrains)** is the one that matters for you: it standardizes how coding agents plug into editing environments, with a live registry inside Zed and JetBrains since January 2026 listing Claude Code, Gemini CLI, Codex (via the community `codex-acp` bridge), and Copilot CLI.

The strategic call for a greenfield product: **implement ACP as a client so you can drive existing coding agents (Claude Code, Codex, Gemini) as the backing intelligence, and consume MCP for tools.** Do not build your own coding agent; the labs will out-model you every quarter (Conductor’s founder is explicit that being provider-agnostic is the durable position).  Your product is the multiplayer session, the steering-and-attribution layer, and the security envelope wrapped around whatever agent is best this month.

### Go-to-market and defensibility

- **Who buys.** The realistic wedge for a solo founder is not greenfield feature development (Conductor, Cursor, and Claude Code own that) but the moments teams already crowd around one problem: production incident response, on-call debugging, and mentoring/onboarding where a senior watches and steers a junior’s agent session live. Claude Code issue #60082’s own use cases (pair programming, mentoring, a senior intervening in a junior’s session) name this exactly.
- **Defensibility is thin.** Anthropic (Claude Tag, and the open #60082 request), GitHub (Ace), Cursor, and Zed can all ship shared sessions natively, and GitHub has already built the prototype. Honest assessment: you do not out-build GitHub on GitHub’s turf. The narrow, defensible positions are (1) agent-agnostic, so a team standardizes on your collaboration and audit layer regardless of which lab’s model wins; (2) the steering, role, and tamper-evident attribution model, which is genuine engineering the incumbents have not prioritized; and (3) verticalized incident-response workflow integrations (PagerDuty, Sentry, runbooks) that a horizontal platform will not build early.
- **Pricing.** The agent-tooling market in 2026 runs per-seat (GitHub Copilot Enterprise $39/user/month;  Cursor and Claude Code base tiers around $20/month) and increasingly usage-based/pay-as-you-go with zero platform markup (Sourcegraph Amp).  Session-hours or steered-sessions is a natural metering unit for a multiplayer product. Conductor’s caution is instructive: it raised $22M and remains free with paid collaboration features unshipped, which tells you monetizing the collaboration layer is unproven.

## Details

### Recommended architecture (implementation brief for Claude Code)

1. **Session actor.** One Cloudflare Durable Object per session (`getByName(sessionId)`). It owns the append-only event log in embedded SQLite (`events(seq INTEGER PK, ts, author_id, type, payload, prev_hash, hash)`), the participant roster with roles, and the WebSocket connections. Use the WebSocket Hibernation API with `serializeAttachment`/`deserializeAttachment` to survive hibernation, so an idle session with watchers costs no duration billing.
1. **Fan-out and replay.** On `onMessage`, append the event, then `this.broadcast` to connected viewers. Late joiners call an HTTP endpoint that returns the latest checkpoint plus events from a requested `seq` offset (the Vercel Workflow `startIndex` pattern, implemented against SQLite, no Redis needed). Keep per-connection cursor state in the socket attachment.
1. **Agent execution.** The DO does not run the model. It spawns/attaches to a per-session microVM (E2B or Cloudflare Sandbox) that runs a coding agent driven over ACP. The DO is the ACP client: it sends `session/prompt`, receives `session/update` streams (agent_message_chunk, tool_call, tool_call_update), forwards them into the event log, and issues `session/cancel` on hard-interrupt. Tool approvals flow through `session/request_permission`, surfaced to the Driver.
1. **Steering.** Human messages are appended as events with author identity, held in an intervention queue, and delivered to the agent at the next tool-call boundary (matching Codex/Cursor/Claude behavior). Hard-interrupt (Escape-equivalent) issues `session/cancel` and immediately re-prompts with the queued human message. Only the Driver’s messages and approvals are authoritative; Navigator suggestions queue behind them; Observers are read-only.
1. **Security envelope.** An outbound redaction pass runs on every event before broadcast, scanning for secrets and applying per-role redaction. Agent credentials are short-lived, session-scoped, injected into the sandbox at boot (never into the prompt). The event log is hash-chained for tamper evidence.
1. **Co-edited sub-surfaces.** A shared plan/scratchpad uses Yjs (or Liveblocks if you want presence and comments for free) relayed through the same DO; this is the only place a CRDT earns its complexity.

### Known hard edges and failure modes

- **Cloudflare single-threaded bottleneck.** One DO is single-threaded; a very hot session with hundreds of viewers all sending messages can queue. Mitigate by keeping the DO’s per-message work minimal (append plus broadcast) and pushing heavy work to the sandbox.
- **WebSocket billing at scale.** The 20:1 incoming-message ratio is favorable, but token-level streaming multiplied by many viewers can still add up; broadcast is outbound and free, but chatty human input is not. Batch where possible.
- **Resumable-stream gaps.** The AI SDK Redis package does not handle tab-switch suspension or multi-device fan-out; your SQLite-offset approach must handle these explicitly or you will ship the same bug OpenAI-style chat apps shipped.
- **Steering incoherence.** Multiple concurrent injections into one context window degrade the agent. The role model and single-Driver authority are not optional polish; they are correctness.
- **Prompt injection through a steerer or through repo content.** With attack success at 63% over 100 attempts in Anthropic’s own agentic-coding measurement,  assume a determined insider or a poisoned file can redirect the agent. Human approval gates on side-effecting tools (the ACP `request_permission` path) are the load-bearing control.
- **Checkpoint illusion.** Do not promise “rewind” for anything that hit a remote system. Compensation and idempotency, not rollback, for external side effects.
- **Incumbent risk.** GitHub Ace and Claude Tag can subsume this. Ship fast, stay agent-agnostic, and own a vertical workflow the platforms will not.

### Where the evidence is thin or conflicting

- **Multi-human steering has no production prior art.** Every mechanism above for concurrent steering is synthesized from single-user agent behavior plus robotics/HCI shared-control theory. It is unproven at the interaction level and is the single biggest product risk. Treat the role model as a hypothesis to test in week one, not a settled design.
- **Some 2026 sources are secondary or promotional.** Cold-start and pricing numbers for sandboxes vary by source (Daytona quoted between 27ms and 150ms depending on configuration);   treat vendor marketing figures as directional and benchmark before committing.
- **Claude Tag and Ace details** come from vendor posts and one talk transcript; exact APIs are not public. The competitive read is directionally solid but the specifics will move.
- **Monetization of the collaboration layer is unproven**, as Conductor’s still-free status shows.

## Recommendations

**Stage 1 (weeks 1 to 4): prove the interaction, not the infra.** Build the thinnest possible vertical slice: one Durable Object session, an ACP client driving Claude Code in an E2B sandbox, token fan-out to 2-3 browser viewers over WebSocket, and the three-role steering model (Driver/Navigator/Observer) with a between-steps intervention queue and a hard-interrupt. The benchmark that matters: can two engineers actually co-steer one debugging session without producing incoherent agent behavior? If concurrent steering degrades output even with the role model, that is a pivot signal.

**Stage 2 (weeks 5 to 10): make it safe and durable.** Add the hash-chained attributed event log, offset-based late-joiner replay against SQLite, per-role secret redaction on the outbound stream, session-scoped short-lived credentials, and ACP `request_permission` approval gates on side-effecting tools. Benchmark: a red-team prompt-injection attempt through both a steerer and a poisoned repo file should not exfiltrate a secret to an Observer.

**Stage 3 (weeks 11 to 16): pick the vertical wedge.** Integrate with one incident-response surface (Sentry or PagerDuty) so a shared agent session spins up from an alert with the right context preloaded. Meter by steered-session or session-hour. Benchmark: an on-call team resolves a real incident faster with shared steering than with screen-share plus copy-paste, which is the status-quo workaround Claude Code issue #60082 documents.

**Thresholds that change the plan.** If Anthropic ships live multi-user Claude Code sessions (the #60082 request) or GitHub GAs Ace before Stage 3, abandon the horizontal play and go all-in on the agent-agnostic audit layer and vertical workflows, which they will not build. If concurrent steering proves fundamentally incoherent regardless of role model, pivot to high-fidelity synchronous *observation* plus explicit single-driver handoff (still valuable, less ambitious). If sandbox or Durable Object costs dominate unit economics at pilot scale, move heavy agent execution to a cheaper substrate (Fly.io Machines or self-hosted Firecracker) and keep only the session actor on Cloudflare.

## Caveats

- Prices, model versions, and product features cited are from mid-2026 sources and move fast; re-verify sandbox pricing, Durable Object billing, and Claude Code/Codex steering behavior against primary docs before committing code, because several of these (the Claude Code queue-versus-interrupt behavior in particular) changed within 2026 and the docs lagged the code.
- The single largest uncertainty is the interaction design for concurrent human steering, which no shipping product has solved and which the academic prior art only addresses for two-party (human plus autonomy) shared control, not N-human shared control. Build to learn here first.
- Defensibility against Anthropic, GitHub, Cursor, and Zed is real but narrow. The plan bets on agent-agnosticism, the steering/attribution model, and vertical workflow depth, none of which is a durable moat on its own; the moat, if there is one, is the combination plus speed.
- Several supporting sources (competitive details on Claude Tag, Ace, and some 2026 sandbox and CRDT benchmark numbers) are secondary or vendor-authored; primary-source figures (Cloudflare limits and pricing, OWASP, Anthropic’s system card, the ACP spec, official Claude Code and Cursor docs, and the Conductor, Temporal, and Modal funding announcements) are the load-bearing ones and are flagged as such in the text.
